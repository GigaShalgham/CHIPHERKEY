# CipherKey Deep-Scan Audit — 2026-11-05 (v0.3.0 re-implementation)

**Scope**: the complete v0.3.0-alpha re-implementation (spec 005) on top of
`749043a`: 30 new or modified main-source files across `app/`,
`data/preferences`, `data/repository` and `security/policies`.

**Method**: machine-verified build (JDK 21, Gradle 8.13, Android SDK 36) with
`testDebugUnitTest` (90 tests / 0 failures), `assembleDebug` and
`assembleRelease`; static scans (logging, secrets, TODO markers, tracked
keystore files); manifest-vs-original comparison (`aapt2 dump permissions`
diffed against the recovered v0.3.0 release APK); module-by-module review of
every new file; re-verification of each finding against the code before and
after the fix.

---

## 1. Executive summary

The re-implementation is **functionally faithful** to the recovered APK: the
merged permission list is byte-identical, the settings keys, notice taxonomy,
biometric AAD scheme (`"contactId:eraId"`), blob format (`IV || GCM`) and
service design all match the decompiled evidence.

The scan found **no CRITICAL findings in the crypto path** and **one HIGH
functional bug** in the new UI glue, both fixed in this pass:

| ID | Severity | Area | Finding | Status |
|---|---|---|---|---|
| F1 | HIGH | biometric UI | Remember-prompt race: the exported session key was pre-loaded into composition state and read by a `LaunchedEffect` keyed only on the request — the effect always ran while the buffer was still `null`, so "Remember this key" could only ever report failure. | **Fixed** — the export is now a suspend loader awaited *inside* the prompt effect (`BiometricPromptHost(loadRememberKey = …)`). |
| F2 | MEDIUM | assistant | Enabling the assistant without the overlay permission, then granting the permission in system settings, started nothing until the next app launch. | **Fixed** — `SettingsViewModel.refresh()` (now resume-driven via `LifecycleResumeEffect`) idempotently converges enabled+granted → running. |
| F3 | MEDIUM | home | Status chips went stale: `saveState/restoreState` navigation kept the Home composable alive, so `LaunchedEffect(Unit)` never re-ran after actions in other tabs. | **Fixed** — `LifecycleResumeEffect` re-reads counters on every Home resume. |
| F4 | LOW | service | Dead `ACTION_STOP` intent path never sent by any caller (stop goes through `stopService`). | **Removed**. |
| F5 | LOW | activity | Unused `LocalContext` import in `MainActivity`. | **Removed**. |
| F6 | INFO | assistant | `POST_NOTIFICATIONS` is declared but not requested at runtime (API 33+): the foreground-service notification is silently hidden until the user grants it in app settings. | **Documented** — matches the original v0.3.0 APK's behavior; changing it would deviate from the recovered build. |

## 2. Verified-by-construction (no finding)

- **Keystore wrap path**: the wrap key is generated with
  `setUserAuthenticationRequired(true)` and, on API 30+,
  `setUserAuthenticationParameters(0, AUTH_BIOMETRIC_STRONG)` — Android will
  not run the cipher without a live biometric authorization, which only the
  system `BiometricPrompt.CryptoObject` path provides.
- **Era-rotation safety**: AAD binds every wrap to `"contactId:eraId"`;
  after an era rotation the GCM authentication fails, the stale blob is
  cleared (`store.clear`), and the user falls back to the passphrase
  (`notice_biometric_stale`). A wrap can never unlock the wrong era.
- **Buffer hygiene**: `exportSessionKey()` returns a copy;
  `unlockContactWithKey()` and `BiometricPromptHelper.rememberKey()` wipe the
  plaintext buffer on every path (success, failure, cancel).
- **Disable means delete**: turning fingerprint unlock off calls
  `clearAll()` — every blob AND the Keystore wrap key are deleted; nothing
  encrypted under the old key remains recoverable.
- **Assistant does no crypto**: the overlay only launches the audited
  companion activities with the clipboard extra; focus-gated clipboard reads
  (spec 004) still apply.
- **No logging, no secrets, no network**: the new packages contain no `Log.*`
  / `println`, no credentials, and no network code; no keystore files are
  tracked.
- **Permission parity**: `aapt2 dump permissions` on the new debug APK
  matches the original v0.3.0 release APK exactly (six uses-permissions plus
  the AndroidX marker).
